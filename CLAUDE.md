## Project Overview

Chrome MV3 browser extension (WXT framework) that automates course evaluations and exports schedules for NJUPT's 正方教务系统. Inject UI panels into ASP.NET pages via Shadow DOM, handling iframe-embedded content and postback-driven page reloads.

## Commands

```bash
npm run dev          # Dev mode with HMR (load .output/chrome-mv3/ unpacked)
npm run build        # Production build → .output/chrome-mv3/
npm run zip          # Production zip for distribution
npm run typecheck    # tsc --noEmit
npm run test         # vitest run (jsdom environment)
npm run check        # Full check: typecheck + test + build
npm test -- --reporter=verbose src/content/eval-strategy.test.ts  # Single test file
```

CI (`.github/workflows/ci.yml`) runs `npm ci` → `prepare:wxt` → `typecheck` → `test` → `build` → `zip`. Tag pushes trigger GitHub Release.

## Architecture

### Entry Points (WXT Content Scripts)

Two independent content scripts, each injecting its own ShadowRoot UI:

| Entry | Matches | Purpose |
|---|---|---|
| `entrypoints/eval-panel.content/` | `jwxt.njupt.edu.cn/*` | Main panel on all pages: page detection, eval automation, dashboard nav |
| `entrypoints/schedule.content/` | `*/xskbcx.aspx*` | Schedule-export button only |

`wxt.config.ts` registers `@wxt-dev/module-react` and `@tailwindcss/vite`. `tsconfig.json` extends `.wxt/tsconfig.json` (auto-generated by `wxt prepare`).

### Eval System (`src/content/`)

Five modules with a strict dependency chain:

1. **`page-detector.ts`** — URL-based page type detection + 3-layer iframe probing (contentWindow → src attribute → contentDocument). Pages: `xs_jsmydpj.aspx` (satisfaction), `xsjxpj.aspx` (teaching-eval), `xskbcx.aspx` (schedule), `xs_main.aspx` (dashboard).

2. **`dom-analyzer.ts`** — Parses ASP.NET DataGrid tables: finds `#pjkc` course selector, extracts `<select id="DataGrid1__ctlN_JS{M}">` elements, groups them by teacher column suffix (`JS1`, `JS2`, …). Also locates the comment box (`#pjxx`), save button (`#Button1`), and submit button (`#Button2`). Uses `getEvalDocument()` which auto-detects whether the eval UI is in a top-level page or an iframe.

3. **`eval-strategy.ts`** — `computeFillActions(groups)` takes `TeacherGroup[]` and returns `FillAction[]` (selectId → value). For each teacher: randomly picks 1 question as "次高分" (index 2), rest as "最高分" (index 1). Auto-detects scale by reading `options[1]`/`options[2]` text from first select — works for both satisfaction (`完全认同`/`相对认同`) and teaching eval (`好`/`较好`).

4. **`dom-fill.ts`** — Applies `FillAction[]` to DOM: sets select values + dispatches `change` events. Also handles comment textarea, save/submit button clicks, and course switching via `__doPostBack('pjkc', '')`.

5. **`eval-loop.ts`** — The core orchestration. Uses `sessionStorage` (keys: `njupt-eval-loop`, `njupt-eval-status`) to persist state across ASP.NET postback page reloads. Flow: switch course via `__doPostBack` → wait for DataGrid reload (polling up to 15s) → fill + save → page reloads → `maybeResumeEvalLoop()` reads sessionStorage and continues. Auto-resumes on every page load with 500ms delay + iframe load listeners.

**State**: `src/content/store.ts` — Zustand store for UI state (pageType, loopStatus, settings). Settings persist via `chrome.storage.local` (key: `njupt-eval:settings`).

### Schedule System (`src/schedule/`)

- **`parser.ts`** — Parses `#Table1` (NJUPT schedule grid). Handles rowspan/colspan via a 15×8 boolean grid tracker. Extracts course name, teacher, location, week range, odd/even week filter, and time slots. Validates output with `CourseSchema` (Zod).
- **`ics.ts`** — Generates RFC 5545 iCalendar. Key: semester start date (first Monday) → `DTSTART`/`DTEND` computed per course per week. Supports custom time slot mappings. Sets `Asia/Shanghai` timezone.
- **`ScheduleExporter.tsx`** — Date picker modal + export button. Saves chosen date to `chrome.storage.local` (key: `njupt-schedule:startDate`). Reused inside `EvalPanelApp` when pageType is `schedule`.

### UI (`EvalPanelApp.tsx`)

Draggable floating panel + collapsible floating ball (`助`). Drag position and collapsed state persisted to sessionStorage (`njupt-eval-ui`). On eval pages: shows course progress, comment template textarea (editable, saved to chrome.storage), start/stop buttons. On dashboard: quick-nav buttons to satisfaction/teaching-eval/schedule pages.

**Critical pointer-events handling**: WXT's shadow host wrappers are set to `pointer-events: none` to avoid blocking clicks on the underlying page. Only the visible panel uses `pointer-events: auto`.

**Iframe lifecycle**: MutationObserver watches for new iframes → attaches load listeners → polls at 800/2000/4000ms → calls `refreshAndResume()` which re-detects page type + triggers `maybeResumeEvalLoop()`.

## Testing

Tests live co-located with source: `src/**/*.test.ts`. Vitest with jsdom environment. `vitest.config.ts` restricts `include` to `src/**/*.test.ts`. 22 tests across 4 files covering: page detection, DOM parsing, rating strategy, and DOM fill operations. Tests build DOM elements programmatically (no fixtures).

## Key Design Constraints

- **No HMR in content scripts**: WXT content scripts reload the whole extension on change. Use `npm run dev` + reload extension manually in `chrome://extensions/`.
- **ASP.NET postback**: The NJUPT system uses `__doPostBack()` for navigation. Course switching triggers a full page/iframe reload. The eval loop survives this via sessionStorage.
- **Iframe context**: Evaluation pages may load directly or inside iframes on `xs_main.aspx`. Always use `getEvalDocument()` (from `dom-analyzer`) to get the correct document.
- **Alert suppression**: The entrypoint patches `window.alert`/`window.confirm` at `document_start` to suppress ASP.NET save confirmation popups.
- **Dual hosts**: The extension matches both `jwxt.njupt.edu.cn` and `202.119.225.134` (direct IP).
